[Tutorial] On Pattern Indexing Using Suffix Arrays

2024-11-29 · Originally published on Codeforces

Hello, Codeforces!

I want to share an algorithm and implementation for the Indexing Problem: given a text string TTT, we want to answer online queries of, given a pattern, how many times it occurs in the text.

For some query defined by a pattern PPP, the indexing problem can be solved using suffix arrays in O(∣P∣log⁡∣T∣)\mathcal O(|P| \log |T|)O(∣P∣log∣T∣) time, as described in edu and my other blog. Here, I will describe a solution in O(∣P∣+log⁡∣T∣)\mathcal O(|P| + \log |T|)O(∣P∣+log∣T∣) time, also using suffix arrays, from the original paper introducing the suffix array [1]. The description from the paper is good, although their pseudocode, it seems, has bugs.

Using suffix arrays makes sense (instead of suffix trees, for example) because they can be build in linear time, even if the alphabet is Θ(∣T∣)\Theta(|T|)Θ(∣T∣). For large alphabets, suffix trees will always have an extra logarithmic factor in the time complexity, unless we use hashing… but who wants that, right?

UPD: this problem was also discussed in this blog.

The Indexing Algorithm

Now, for the solution. Remember that the indices where any pattern occurs in the text is a range in the suffix array. We will compute the first and last index of the range independently.

To optimize from the O(∣P∣log⁡∣T∣)\mathcal O(|P| \log |T|)O(∣P∣log∣T∣) time implementation (a simple binary search with O(∣P∣)\mathcal O(|P|)O(∣P∣) time string comparison), we will use the lcplcplcp information. We will use the type of binary search that maintains that the answer is in the open range (L,R)(L, R)(L,R) [2].

At every iteration of the binary search, we maintain two values lll and rrr, the lcplcplcp between PPP and the suffixes Tsa[L]T_{sa[L]}Tsa[L]​ and Tsa[R]T_{sa[R]}Tsa[R]​, respectively. Here, we use the notation TiT_iTi​ for the suffix of TTT starting at index iii. Also, sasasa is the suffix array.

Now, we need to compute lcp(P,Tsa[M])lcp(P, T_{sa[M]})lcp(P,Tsa[M]​), and then the next character will tell us what side of the binary search we need to go to. For that, let us assume that l≥rl \geq rl≥r (the other case will be symmetric). We now compare lll with lcp(Tsa[L],Tsa[M])lcp(T_{sa[L]}, T_{sa[M]})lcp(Tsa[L]​,Tsa[M]​) (assume we have this value precomputed). We have two cases:

  1. lcp(Tsa[L],Tsa[M])<llcp(T_{sa[L]}, T_{sa[M]}) \lt llcp(Tsa[L]​,Tsa[M]​)<l: in this case, lcp(P,Tsa[M])=lcp(Tsa[L],Tsa[M])lcp(P, T_{sa[M]}) = lcp(T_{sa[L]}, T_{sa[M]})lcp(P,Tsa[M]​)=lcp(Tsa[L]​,Tsa[M]​), because PPP matches lll characters from Tsa[L]T_{sa[L]}Tsa[L]​, and Tsa[L]T_{sa[L]}Tsa[L]​ matches less than lll characters from Tsa[M]T_{sa[M]}Tsa[M]​.
  2. lcp(Tsa[L],Tsa[M])≥llcp(T_{sa[L]}, T_{sa[M]}) \geq llcp(Tsa[L]​,Tsa[M]​)≥l: now we can find the smallest i>li \gt li>l such that P[i]≠Tsa[M][i]P[i] \neq T_{sa[M]}[i]P[i]=Tsa[M]​[i], and assign lcp(P,Tsa[M])=ilcp(P, T_{sa[M]}) = ilcp(P,Tsa[M]​)=i.

It turns out that if we do case 2 naively and update our (l,r)(l, r)(l,r) accordingly, the total cost of these comparisons is O(∣P∣)\mathcal O(|P|)O(∣P∣), because each time we increase max⁡(l,r)\max(l, r)max(l,r), and these values can only increase up to ∣P∣|P|∣P∣. Also, on case case 1 we always go left on the binary search (because r≤lcp(Tsa[L],Tsa[M])<lr \leq lcp(T_{sa[L]}, T_{sa[M]}) \lt lr≤lcp(Tsa[L]​,Tsa[M]​)<l), thus maintaining or increasing the value of rrr. In fact, both lll and rrr never decrease.

We are left to precomputing LLL_lcp[M]=lcp(Tsa[L],Tsa[M])lcp[M] = lcp(T_{sa[L]}, T_{sa[M]})lcp[M]=lcp(Tsa[L]​,Tsa[M]​) and RRR_lcp[M]=lcp(Tsa[R],Tsa[M])lcp[M] = lcp(T_{sa[R]}, T_{sa[M]})lcp[M]=lcp(Tsa[R]​,Tsa[M]​) for every possible range we visit in the binary search. But this is easy: we can just recursively go through every (L,R)(L, R)(L,R) pair we can visit in a binary search, and store the lcplcplcp value of the range. Note that the value of MMM uniquely identifies the range.

Lcp precomputation

int lcp_precalc(int L, int R) {
	if (R - L <= 1) return lcp[L]; // lcp between T_sa[L] and T_sa[L+1]
	int M = (L+R)/2;
	L_lcp[M] = lcp_precalc(L, M);
	R_lcp[M] = lcp_precalc(M, R);
	return min(L_lcp[M], R_lcp[M]);
}
lcp_precalc(0, n-1);

The full code is seen below. The last boolean indicates if the first index of the range or the first index not in the range is to be computed. The number of occurrences is then the difference between the values. If PPP does not occur in TTT, the code returns the empty range [n,n)[n, n)[n,n). The last check in the code refers to the pattern not occurring (see next section).

Code

int get_idx(string& p, bool first) {
	auto extend_lcp = [&](int l, int i) {
		while (l < p.size() and sa[i]+l < t.size() and p[l] == t[sa[i]+l]) l++;
		return l;
	};
	int l = extend_lcp(0, 0), r = extend_lcp(0, t.size()-1);
 
	// occurs at idx 0
	if (first and l == p.size()) return 0;
	// occurs at idx n-1
	if (!first and r == p.size()) return t.size();
 
	int L = 0, R = t.size()-1;
	while (R - L > 1) {
		int M = (L+R)/2;
		int m;
		if (l >= r) m = L_lcp[M] < l ? L_lcp[M] : extend_lcp(l, M);
		else m = R_lcp[M] < r ? R_lcp[M] : extend_lcp(r, M);
 
		bool eq = m == p.size();
		bool greater = !eq and sa[M]+m < t.size() and p[m] < t[sa[M]+m];
 
		bool right = first and (greater or eq);
		right |= !first and greater;
 
		if (right) R = M, r = m;
		else L = M, l = m;
	}
	return max(l, r) < p.size() ? t.size() : R;
}

Largest Occurring Prefix

Note that, at the end of the algorithm, k = max(l, r) is the largest prefix of PPP that occurs in TTT. It is not hard to see that the algorithm actually runs in O(k+log⁡∣T∣)\mathcal O(k + \log |T|)O(k+log∣T∣). This allows us to compute, for example, the minimum size partition of PPP such that every element occurs in TTT in O(∣P∣log⁡∣T∣)\mathcal O(|P| \log |T|)O(∣P∣log∣T∣) time.
