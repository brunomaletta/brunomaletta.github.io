tgen::miniblog(4): random trees

2026-09-12 · Originally published on Codeforces

This is a blog 4 of a series of blogs about algorithmic challenges I came across when creating tgen.

In this blog we will tackle:

  1. Generate a uniformly random tree on vertices [0,n)[0, n)[0,n) given some preset edges, in O(n)\mathcal O(n)O(n) time.
  2. Generate a skewed tree on vertices [0,n)[0, n)[0,n) in O(n)\mathcal O(n)O(n) time.

1. Uniform random tree with preset edges

Sometimes we want to force some edges to appear in the tree, for example because the test needs a specific path or star substructure. The preset edges may span several connected components; we need to connect those components into a single tree.

The key tool is the Prüfer sequence. Every labeled tree on kkk vertices corresponds to a unique sequence of length k−2k-2k−2 with entries in [0,k)[0, k)[0,k), and the degree of vertex iii in the tree is one plus its frequency in the sequence. A uniform random Prüfer sequence therefore gives a uniform random labeled tree.

When there are preset edges, the components play the role of super-vertices: we want to connect ccc components into a tree, which requires exactly c−1c-1c−1 new edges. The new tree on ccc super-vertices is generated via a random Prüfer sequence of length c−2c-2c−2. Larger components need to be more likely to be chosen, because they have more vertices that can be edge endpoints, so we sample each Prüfer entry with probability proportional to the component size using the alias method. For each new edge, a concrete vertex in each of its two components is then picked uniformly at random.

// c = number of components, comp_size[i] = size of component i
// component_ids[i] = list of vertex ids in component i
// many_by_distribution uses the alias method; returns i with probability proportional to comp_size[i]
std::vector<int> prufer = many_by_distribution(c - 2, comp_size);
for (auto [u, v] : edges_from_prufer(prufer))
    new_edges.emplace_back(pick(component_ids[u]), pick(component_ids[v]));

2. Skewed tree

A uniformly random labeled tree has expected height Θ(n)\Theta(\sqrt n)Θ(n​) (see this comment). If the parent of iii is next(0, i-1), we get a classical random recursive tree, and the diameter is typically Θ(log⁡n)\Theta(\log n)Θ(logn). To force a star, we want that parent to be close to 000; to force a path (a skewed tree, with endpoints 000 and n−1n-1n−1), we want it close to i−1i-1i−1.

That bias is exactly wnext. For e≥0e \geq 0e≥0, wnext(i, e) is the maximum of e+1e+1e+1 independent samples of next(0, i-1) (so it is biased toward i−1i-1i−1). For e<0e \lt 0e<0, it is the minimum of ∣e∣+1|e|+1∣e∣+1 samples (biased toward 000).

int wnext(int i, int e) {
	int j = next(0, i - 1);
	if (e >= 0) {
		for (int t = 0; t < e; t++)
			j = std::max(j, next(0, i - 1));
	} else {
		for (int t = 0; t < std::abs(e); t++)
			j = std::min(j, next(0, i - 1));
	}
	return j;
}

std::vector<std::pair<int, int>> gen_skewed(int n, int e) {
	std::vector<std::pair<int, int>> edges;
	for (int i = 1; i < n; i++)
		edges.push_back({wnext(i, e), i});
	return edges;
}

If eee is 000, this is the uniform recursive tree. If eee is negative and large in absolute value, this is likely a star centered at 000. If eee is large, this is likely a path with endpoints 000 and n−1n-1n−1.

In particular, as eee grows, wnext(i, e) concentrates on j=i−1j = i-1j=i−1, so vertex iii connects to i−1i-1i−1 with probability tending to 111. For e<0e \lt 0e<0, it concentrates on j=0j = 0j=0.

The loop above runs in O(∣e∣)\mathcal O(|e|)O(∣e∣) time, which is too slow for large ∣e∣|e|∣e∣. The same distribution can be sampled in O(1)\mathcal O(1)O(1) by inverse transform:

int wnext(int i, int e) {
	double r = next(0.0, 1.0);
	double x;
	if (e >= 0)
		x = std::pow(r, 1.0 / (e + 1));
	else
		x = 1.0 - std::pow(r, 1.0 / (std::abs(e) + 1));
	return (int)(x * i); // in [0, i)
}

Algorithm 3: wnext in O(1)\mathcal O(1)O(1) time.
