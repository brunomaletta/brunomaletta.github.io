[Tutorial] Range minimum query in O(1) with linear time construction

2020-06-16 · Originally published on Codeforces

TL; DR

Build a sparse table over blocks of size b=30≥log⁡nb = 30 \geq \log{n}b=30≥logn. Now we only need to answer queries of size smaller than bbb. For that, simulate a minqueue of size bbb over the array, and store a mask of the elements that are currently active in the minqueue. Let mask[r]\text{mask[r]}mask[r] be the minqueue mask when the simulation is at position r\text{r}r. Now we can see that, if r−l+1≤br-l+1 \leq br−l+1≤b, then query(l, r) = r - most_significant_set_bit(mask[r] & ((1<<(r-l+1))-1)).

template<typename T> struct rmq {
	vector<T> v;
	int n; static const int b = 30;
	vector<int> mask, t;

	int op(int x, int y) { return v[x] < v[y] ? x : y; }
	int msb(int x) { return __builtin_clz(1)-__builtin_clz(x); }
	int small(int r, int sz = b) { return r-msb(mask[r]&((1<<sz)-1)); }
	rmq(const vector<T>& v_) : v(v_), n(v.size()), mask(n), t(n) {
		for (int i = 0, at = 0; i < n; mask[i++] = at |= 1) {
			at = (at<<1)&((1<<b)-1);
			while (at and op(i, i-msb(at&-at)) == i) at ^= at&-at;
		}
		for (int i = 0; i < n/b; i++) t[i] = small(b*i+b-1);
		for (int j = 1; (1<<j) <= n/b; j++) for (int i = 0; i+(1<<j) <= n/b; i++)
			t[n/b*j+i] = op(t[n/b*(j-1)+i], t[n/b*(j-1)+i+(1<<(j-1))]);
	}
	T query(int l, int r) {
		if (r-l+1 <= b) return v[small(r, r-l+1)];
		int ans = op(small(l+b-1), small(r));
		int x = l/b+1, y = r/b-1;
		if (x <= y) {
			int j = msb(y-x+1);
			ans = op(ans, op(t[n/b*j+x], t[n/b*j+y-(1<<j)+1]));
		}
		return v[ans];
	}
};

Hello, Codeforces!

Here I’ll share an algorithm to solve the classic problem of Range Minimum Query (RMQ): given a static array AAA (there won’t be any updates), we want to find, for every query(l, r)\text{query(l, r)}query(l, r), the index of the minimum value of the sub-array of AAA that starts at index l\text{l}l and ends at index r\text{r}r. That is, we want to find query(l, r)=arg minl≤i≤r(A[i])\text{query(l, r)} = \text{arg min}_{l \leq i \leq r}{\left(A[i]\right)}query(l, r)=arg minl≤i≤r​(A[i]). If there are more than one such indices, we can answer any of them.

I would like to thank tfg for showing me this algorithm. If you have read about it somewhere, please share the source. The only source I could find was a comment from jcg, where he explained it briefly.

Introduction

Sparse table is a well known data structure to query for the minimum over a range in constant time. However, it requires Θ(nlog⁡n)\Theta(n \log n)Θ(nlogn) construction time and memory. Interestingly, we can use a sparse table to help us answer RMQ with linear time construction: even though we can’t build a sparse table over all the elements of the array, we can build a sparse table over fewer elements.

To do that, let us divide the array into blocks of size bbb and compute the minimum of each block. If we then build a sparse table over these minimums, it will cost O(nblog⁡nb)⊆O(nblog⁡n)\mathcal{O}(\frac{n}{b} \log{\frac{n}{b}}) \subseteq \mathcal{O}(\frac{n}{b} \log{n})O(bn​logbn​)⊆O(bn​logn). Finally, if we choose b∈Θ(log⁡n)b \in \Theta(\log n)b∈Θ(logn), we get O(n)\mathcal{O}(n)O(n) time and space for construction of the sparse table!

So, if our query indices happen to align with the limits of the blocks, we can find the answer. But we might run into the following cases:

  • Query range is too small, so it fits entirely inside one block:

  • Query range is large and doesn’t align with block limits:

Note that, on the second case, we can use our sparse table to query the middle part (in gray). In both cases, if were able to make small queries (queries such that r−l+1≤br-l+1 \leq br−l+1≤b), we would be done.

Handling small queries

Let’s consider queries ending at the same position rrr. Take the following array AAA and r=6r = 6r=6.

Obviously, query(6,6)=6\text{query}(6, 6) = 6query(6,6)=6. Since query(5,6)=5≠query(6,6)\text{query}(5, 6) = 5 \neq \text{query}(6, 6)query(5,6)=5=query(6,6), we can think of the position 5\text{5}5 as “important”. Position 4\text{4}4, though, is not important, because query(4,6)=5=query(5,6)\text{query}(4, 6) = 5 = \text{query}(5, 6)query(4,6)=5=query(5,6). Basically, for fixed rrr, a position is important if the value at that position is smaller than all the values to the right of it. In this example, the important positions are 6,5,2,06, 5, 2, 06,5,2,0. In the following image, important elements are represented with 1\text{1}1 and others with 0\text{0}0.

Since we only have to answer queries with size at most b∈Θ(log⁡n)b \in \Theta(\log n)b∈Θ(logn), we can store this information in a mask of size bbb: in this example mask[6] = 1010011\text{mask[6] = 1010011}mask[6] = 1010011, assuming b≥7b \geq 7b≥7. If we had these masks for the whole array, how could we figure out the minimum over a range? Well, we can simply take mask[r]\text{mask[r]}mask[r], look at it’s r−l+1r-l+1r−l+1 least significant bits, and out of those bits take most significant one! The index of that bit would tell us how far away from rrr the answer is.

Using our previous example, if the query was from 1\text{1}1 to 6\text{6}6, we would take mask[6]\text{mask[6]}mask[6], only look at the r−l+1=6r-l+1=6r−l+1=6 least significant bits (that would give us 010011\text{010011}010011) and out of that take the index of the most significant set bit: 4\text{4}4. So the minimum is at position r−4=2r - 4 = 2r−4=2.

Now we only need to figure out how to compute theses masks. If we have some mask representing position rrr, lets change it to represent position r+1r+1r+1. Obviously, a position that was not important can’t become important, so we won’t need to turn on any bits. However, some positions that were important can stop being important. To handle that, we can just keep turning off the least significant currently set bit of our mask, until there are no more bits to turn off or the value at r+1r+1r+1 is greater than the element at the position represented by the least significant set bit of the mask (in that case we can stop, because the elements represented by important positions to the left of the least significant set bit are even smaller).

Let’s append an element with value 3\text{3}3 at the end of array AAA and update our mask.

Since A[6] \gt3\text{A[6] \gt 3}A[6] \gt3, we turn off that bit. After that, once again A[5] \gt3\text{A[5] \gt 3}A[5] \gt3, so we also turn off that bit. Now we have that A[2] \lt3\text{A[2] \lt 3}A[2] \lt3, so we stop turning off bits. Finally, we need to append a 1 to the right of the mask, so it becomes mask[7] = 10100001\text{mask[7] = 10100001}mask[7] = 10100001 (assuming b≥8b \geq 8b≥8).

This process takes O(n)\mathcal{O}(n)O(n) time: only one bit is turned on for each position of the array, so the total number of times we turn a bit off at most nnn, and using bit operations we can get and turn off the least significant currently set bit in O(1)\mathcal{O}(1)O(1).

Implementation

Here is a detailed C++ implementation of the whole thing.

template<typename T> struct rmq {
	vector<T> v; int n;
	static const int b = 30; // block size
	vector<int> mask, t; // mask and sparse table

	int op(int x, int y) {
		return v[x] < v[y] ? x : y;
	}
	// least significant set bit
	int lsb(int x) {
		return x & -x;
	}
	// index of the most significant set bit
	int msb_index(int x) {
		return __builtin_clz(1)-__builtin_clz(x);
	}
	// answer query of v[r-size+1..r] using the masks, given size <= b
	int small(int r, int size = b) {
		// get only 'size' least significant bits of the mask
		// and then get the index of the msb of that
		int dist_from_r = msb_index(mask[r] & ((1<<size)-1));

		return r - dist_from_r;
	}
	rmq(const vector<T>& v_) : v(v_), n(v.size()), mask(n), t(n) {
		int curr_mask = 0;
		for (int i = 0; i < n; i++) {

			// shift mask by 1, keeping only the 'b' least significant bits
			curr_mask = (curr_mask<<1) & ((1<<b)-1);

			while (curr_mask > 0 and op(i, i - msb_index(lsb(curr_mask))) == i) {
				// current value is smaller than the value represented by the
				// last 1 in curr_mask, so we need to turn off that bit
				curr_mask ^= lsb(curr_mask);
			}
			// append extra 1 to the mask
			curr_mask |= 1;

			mask[i] = curr_mask;
		}

		// build sparse table over the n/b blocks
		// the sparse table is linearized, so what would be at
		// table[j][i] is stored in table[(n/b)*j + i]
		for (int i = 0; i < n/b; i++) t[i] = small(b*i+b-1);
		for (int j = 1; (1<<j) <= n/b; j++) for (int i = 0; i+(1<<j) <= n/b; i++)
			t[n/b*j+i] = op(t[n/b*(j-1)+i], t[n/b*(j-1)+i+(1<<(j-1))]);
	}
	// query(l, r) returns the actual minimum of v[l..r]
	// to get the index, just change the first and last lines of the function
	T query(int l, int r) {
		// query too small
		if (r-l+1 <= b) return v[small(r, r-l+1)];

		// get the minimum of the endpoints
		// (there is no problem if the ranges overlap with the sparse table query)
		int ans = op(small(l+b-1), small(r));

		// 'x' and 'y' are the blocks we need to query over
		int x = l/b+1, y = r/b-1;

		if (x <= y) {
			int j = msb_index(y-x+1);
			ans = op(ans, op(t[n/b*j+x], t[n/b*j+y-(1<<j)+1]));
		}

		return v[ans];
	}
};

But is it fast?

As you might have guessed, although the asymptotic complexity is optimal, the constant factor of this algorithm is not so small. To get a better understanding of how fast it actually is and how it compares with other data structures capable of answering RMQ, I did some benchmarks (link to the benchmark files).

I compared the following data structures. Complexities written in the notation <O(f),O(g)>\lt \mathcal{O}(f), \mathcal{O}(g) \gt<O(f),O(g)> means that the data structure requires O(f)\mathcal{O}(f)O(f) construction time and O(g)\mathcal{O}(g)O(g) query time.

  • RMQ 1 (implementation of RMQ described in this post): <O(n),O(1)>\lt \mathcal{O}(n), \mathcal{O}(1) \gt<O(n),O(1)>;
  • RMQ 2 (different algorithm, implementation by catlak_profesor_mfb, from this blog): <O(n),O(1)>\lt \mathcal{O}(n), \mathcal{O}(1) \gt<O(n),O(1)>;
  • Sparse Table: <O(nlog⁡n),O(1)>\lt \mathcal{O}(n \log n), \mathcal{O}(1) \gt<O(nlogn),O(1)>;
  • Sqrt-tree (tutorial and implementation from this blog by gepardo): <O(nlog⁡log⁡n),O(1)>\lt \mathcal{O}(n \log \log n), \mathcal{O}(1) \gt<O(nloglogn),O(1)>;
  • Standard Segment Tree (recursive implementation): <O(n),O(log⁡n)>\lt \mathcal{O}(n), \mathcal{O}(\log n) \gt<O(n),O(logn)>;
  • Iterative (non recursive) Segment Tree: <O(n),O(log⁡n)>\lt \mathcal{O}(n), \mathcal{O}(\log n) \gt<O(n),O(logn)>.

Conclusion

We have an algorithm with optimal complexity to answer RMQ, and it is also simple to understand and implement. With the benchmark made, we can see that its construction is much faster than Sparse Table and Sqrt-tree, but a little slower than Segment Trees. Its query time seems to be roughly the same as Sqrt-tree, losing only to Sparse Table, which have shown to be the fastest in query time.
