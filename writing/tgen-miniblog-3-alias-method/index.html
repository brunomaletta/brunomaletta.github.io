tgen::miniblog(3): Alias Method

2026-08-19 · Originally published on Codeforces

This is a blog 3 of a series of blogs about algorithmic challenges I came across when creating tgen.

In this blog we will tackle:

  1. Create a data structure with O(n)\mathcal O(n)O(n) time construction that can return i∈[0,n)i \in [0, n)i∈[0,n) with probability proportional to w[i]≥0w[i] \geq 0w[i]≥0 in O(1)\mathcal O(1)O(1) time.

It is trivial to create such a data structure with Θ(log⁡n)\Theta(\log n)Θ(logn) query time: with a prefix sum array ppp with values in [0,S][0, S][0,S], where S=∑iw[i]S = \sum_i w[i]S=∑i​w[i], just pick a uniformly random value x∈[0,S)x \in [0, S)x∈[0,S), and then do a binary search to find and return the first index iii such that p[i]>xp[i] \gt xp[i]>x.

Turns out that we can improve the query to O(1)\mathcal O(1)O(1) time, with linear construction. This is the alias method.

If all weights were the same, S/nS / nS/n, then it would be trivial: just return next(0, n-1). If not, some indices are small (w[i]<S/nw[i] \lt S / nw[i]<S/n), and some are big (w[i]≥S/nw[i] \geq S / nw[i]≥S/n). The idea is to “transfer” the exceeding probability of the small indices to the big ones.

To do that, after we choose a random index i = next(0, n-1), we will either return i with probability mass[i] / S, or return alias[i]. Note that there is no chaining, that is, we don’t follow many alias pointers; we either return i or alias[i]. Now we are left to show that it is always possible to choose an assignment for alias[i] and mass[i] in such a way that the probabilities are maintained.

To start, we scale every weight by nnn to make everything an integer, so outcome iii has mass n⋅w[i]n \cdot w[i]n⋅w[i]. The average scaled mass is exactly SSS. Maintain two queues: small\mathrm{small}small for indices with current mass <S\lt S<S, and big\mathrm{big}big for indices with current mass ≥S\geq S≥S. While both are nonempty, pop sss from small\mathrm{small}small and bbb from big\mathrm{big}big. Index sss is finalized: we keep mass[s]\mathrm{mass}[s]mass[s] as the threshold for returning sss, and set alias[s]=b\mathrm{alias}[s] = balias[s]=b, so the leftover S−mass[s]S - \mathrm{mass}[s]S−mass[s] of the pick is given to bbb. This leftover is at most SSS (since mass[s]≥0\mathrm{mass}[s] \geq 0mass[s]≥0), and mass[b]≥S\mathrm{mass}[b] \geq Smass[b]≥S, so we never subtract more from bbb than it has. After subtracting that leftover from mass[b]\mathrm{mass}[b]mass[b], we put bbb back into the appropriate queue (depending on whether its remaining mass is small or big). Each step permanently finalizes one index.

At the end, all indices remaining in big\mathrm{big}big must have mass exactly SSS (because the existence of an index with mass >S\gt S>S implies another with mass <S\lt S<S), so those indices are finalized as a single outcome (they are their own alias).

struct alias_method {
	int n;
	long long S;
	std::vector<long long> mass;
	std::vector<int> alias;

	alias_method(const std::vector<int>& w) : n(w.size()), alias(n) {
		S = 0;
		for (auto x : w) S += x;

		std::queue<int> small, big;
		for (int i = 0; i < n; i++) {
			mass.push_back(n * w[i]);
			if (mass[i] < S) small.push(i);
			else big.push(i);
		}

		while (!small.empty() and !big.empty()) {
			int s = small.front(); small.pop();
			int b = big.front(); big.pop();

			alias[s] = b;
			mass[b] -= S - mass[s];

			if (mass[b] < S) small.push(b);
			else big.push(b);
		}

		while (!big.empty()) {
			int b = big.front(); big.pop();
			alias[b] = b;
			mass[b] = S;
		}
	}
};

Algorithm 1: alias method construction.

To sample, pick a uniform index and compare a uniform sample in [0,S)[0, S)[0,S) against the threshold stored in that index:

int next(const alias_method& a) {
	int i = next(0, a.n - 1);
	long long x = next(0, a.S - 1);
	return x < a.mass[i] ? i : a.alias[i];
}
